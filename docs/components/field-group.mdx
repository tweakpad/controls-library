## Usage

Field group lays out related editors and joins their borders. It owns only the layout, the seams and the group name: each editor keeps its own value, `name`, label, state and validation, and the group submits nothing itself. `label` names the tuple ("Canvas size"); every editor still needs its own complete `label`, because prefixes like `W` are visual shorthand.

It is the editor counterpart of [Button group](../button-group/) and shares its seam treatment.

To stack separate Fields with spacing, use Field's `group` slot instead.

### Tuples

Editors share the main axis equally. Keep a related value that is not part of the tuple, such as opacity, outside the group so it reads as separate.

An editor that declares its own `inline-size` or `flex` keeps it. Inside a container with a definite inline size the editors shrink below their intrinsic width; an ancestor that is sized by its content (a grid auto track, `fit-content`) keeps each native input's intrinsic minimum, so give such containers an inline size.

### Mixed members

Buttons and Toggles can join beside the editors. A Separator divides editors and takes the perpendicular orientation automatically.

Input, Input group, Text area, Select and Native select are editor members. Button and Toggle can join beside them, and Menu or Popover participate through their slotted trigger; popup content is never a member.

Hidden members (`hidden`) do not participate. Reordering, removing or replacing a member updates the seams and part registrations without replacing other controls. Content that is not a member splits the group into independent seam runs.

<Preview
  title="Separator"
  align="stretch"
  code={`<tp-field-group label="Price range" style="max-inline-size:24rem">
  <tp-input-group><span slot="prefix">$</span><tp-input label="Minimum price" default-value="20"></tp-input></tp-input-group>
  <tp-separator></tp-separator>
  <tp-input-group><span slot="prefix">$</span><tp-input label="Maximum price" default-value="150"></tp-input></tp-input-group>
</tp-field-group>`}
/>

### Member states

Each editor keeps its own state inside the group. A read-only or disabled editor shows its usual treatment while its neighbours stay editable.

Disable or make read-only the editors individually (`disabled`, `readonly`), or wrap the group in a disabled fieldset through Field. The group adds no selection state: it never implies that one member is chosen.

### Orientation

`orientation="vertical"` stacks the editors, stretches them to the widest one and joins their block edges. Use it for long tuples that would become unreadable in one row.

### Inline

<Preview
  title="Inline"
  align="stretch"
  code={`<tp-stack style="max-inline-size: 20rem; margin-inline: auto" gap="2">
  <tp-input variant="inline" label="Layer" default-value="Header card"></tp-input>
  <tp-field-group variant="inline" label="Position">
    <tp-input-group
      ><span slot="prefix">X</span><tp-input label="X" type="number" default-value="120"></tp-input
    ></tp-input-group>
    <tp-input-group
      ><span slot="prefix">Y</span><tp-input label="Y" type="number" default-value="48"></tp-input
    ></tp-input-group>
  </tp-field-group>
  <tp-field-group variant="inline" label="Size">
    <tp-input-group
      ><span slot="prefix">W</span
      ><tp-input label="Width" type="number" default-value="1280"></tp-input
    ></tp-input-group>
    <tp-input-group
      ><span slot="prefix">H</span
      ><tp-input label="Height" type="number" default-value="720"></tp-input
    ></tp-input-group>
  </tp-field-group>
  <tp-field-group variant="inline" label="Rotation">
    <tp-input-group
      ><span slot="prefix">X</span
      ><tp-input label="Rotation X" type="number" min="-180" max="180" default-value="0"></tp-input
    ></tp-input-group>
    <tp-input-group
      ><span slot="prefix">Y</span
      ><tp-input label="Rotation Y" type="number" min="-180" max="180" default-value="45"></tp-input
    ></tp-input-group>
    <tp-input-group
      ><span slot="prefix">Z</span
      ><tp-input label="Rotation Z" type="number" min="-180" max="180" default-value="90"></tp-input
    ></tp-input-group>
  </tp-field-group>
</tp-stack>`}
/>

`variant="inline"` fits the group into one row the height of a control, with `label` at the start and the values at the end, so it stacks with other inline controls such as an inline Input. Each editor becomes a segment of the row: its prefix, then its value, as wide as its text. The row carries the boundary, the focus ring and the invalid state, and a press on the label edits the first value.

Number values step with the Arrow keys, ten steps at a time with Shift, and keep to their `step`, `min` and `max`; a committed value rounds to the decimals of `step`. A value off the step or out of range shows the whole row invalid, and a long value scrolls inside its own segment.

An Icon in the `icon` slot leads the row, outside its boundary. A unit goes in each Input group's `suffix` slot and follows its value.

`expanded` shows each value of an inline group on an indented row of its own below the group's row, with its prefix as its label and its unit after it; each row keeps its own focus ring and invalid state. `expandable` adds a Button at the end of the row that expands and collapses the group and proposes each change with `tp-expanded-change`; with `expanded` alone, the rows always show.

### Constraints

<Preview
  title="Constraints"
  align="stretch"
  code={`<tp-field-group id="field-group-constraints" variant="inline" label="Size" expanded style="max-inline-size:20rem;margin-inline:auto">
  <tp-input-group><span slot="prefix">W</span><tp-input label="Width" name="width" type="number" default-value="1280"></tp-input><span slot="suffix">px</span></tp-input-group>
  <tp-input-group><span slot="prefix">H</span><tp-input label="Height" name="height" type="number" default-value="720"></tp-input><span slot="suffix">px</span></tp-input-group>
</tp-field-group>`}
  script={`document.querySelector('#field-group-constraints').constraints = [
  { rule: 'proportional', members: ['width', 'height'], label: 'Keep aspect ratio', engaged: true },
];`}
/>

`constraints` lists relations the group keeps between its values. Each one names its values by their editors' `name` (or their position among the editors), labels its Toggle and states whether it is `engaged` at first. The `proportional` rule keeps the values in the ratio they had when it took hold. In an expanded group, a bracket joins the related rows around the Toggle that engages and releases the constraint, and `tp-constraint-change` proposes each switch. An engaged constraint holds in every variant.

A function rule computes the other values from the one that changed. Values a constraint writes snap to each editor's step and commit after the value being edited.

<Code
  label="A function rule"
  language="typescript"
  code={`range.constraints = [
  {
    members: ['minimum', 'maximum'],
    label: 'Keep the range width',
    engaged: true,
    // Moving either end moves the other by the same amount.
    rule: ({ source, values, reference }) => {
      const width = reference[1] - reference[0];
      return source === 0 ? [undefined, values[0] + width] : [values[1] - width, undefined];
    },
  },
];`}
/>

### In widgets

The color picker composes a Field group for its channel editors (R/G/B, H/S/L, …, or the single hex editor) and keeps the alpha editor apart with the row gap, so every format reads as one tuple plus opacity.
