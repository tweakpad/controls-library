## Usage

A Scroll Area keeps the browser's own scrolling (wheel, touch, keyboard, focus and scroll anchoring) and replaces only the visible scrollbars. Constrain its height or width; its content decides how far it scrolls. A `label` names the viewport as a region, which helps when it holds a lot of content. Track clicks and drags preserve keyboard focus, temporarily suspend scroll snapping, and restore it on release, cancellation, disabling, removal or disconnection. Track wheel input leaves reached edges unconsumed for ancestor scrolling; control-wheel zoom is untouched.

### Horizontal

`orientation="horizontal"` shows the horizontal track. The content needs an intrinsic width wider than the area, such as a row that does not wrap.

### Scrollbar visibility

`scrollbar-visibility` decides when tracks appear. The default, `while-scrolling`, shows a track only while its axis scrolls, while it is dragged and while the viewport has keyboard focus. `automatic` shows each overflowing axis, `on-hover` shows it while the pointer is over the area, and `always` keeps the track visible as a cue that more content exists.

### Overflow markers

The host exposes `data-overflow-y-start` and `data-overflow-y-end` while content is hidden past an edge. Content fades are off by default. Add `scroll-edge-fade` to enable them on this component. Remove the attribute to disable them. The inherited `--tp-scroll-edge-fade-size` theme token controls their maximum width (24px by default). Scroll the viewport itself with the standard `scrollTo` and `scrollTop` APIs on `viewportElement`. No second scroll position or component change event is maintained. Horizontal offsets follow the native RTL model.
