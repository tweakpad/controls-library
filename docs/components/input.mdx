## Usage

Labels, descriptions and errors belong to `tp-field`; the Input owns the native editor. A standalone Input can take `label` for its accessible name, but a Field is the usual home. Optional prefix and suffix content belongs to `tp-input-group`.

### Types

`type` keeps native editing, affordances and validation for every host-supported input type.

<Preview
  width="3"
  title="Types"
  align="stretch"
  code={`<tp-stack  gap="4">
  <tp-field label="Password">
    <tp-input type="password" name="password" autocomplete="current-password"></tp-input>
  </tp-field>
  <tp-field label="Quantity">
    <tp-input type="number" name="quantity" min="1" max="10" default-value="1"></tp-input>
  </tp-field>
  <tp-field label="Search">
    <tp-input type="search" name="q" placeholder="Search projects"></tp-input>
  </tp-field>
</tp-stack>`}
/>

### Code-like values

`mono` shows the value in the mono font and turns off spell checking, autocorrection and autocapitalization. Use it for identifiers, paths, expressions and keys, where a corrected character is a bug.

<Preview
  width="3"
  title="Mono"
  align="stretch"
  code={`<tp-stack  gap="4">
  <tp-field label="Webhook secret">
    <tp-input mono name="secret" default-value="whsec_9f2b41c07a"></tp-input>
  </tp-field>
  <tp-field label="Branch">
    <tp-input mono name="branch" default-value="release/2026-10"></tp-input>
  </tp-field>
</tp-stack>`}
/>

### Controlled value

`default-value` leaves the text to the Input. Supply `value` instead, before the first render, and every edit becomes a proposal: `onValueChange` receives it, and what you assign back to `value` is what commits. Here the owner rewrites each edit into a URL-safe handle.

<Preview
  width="3"
  title="Owner-shaped value"
  align="stretch"
  code={`<tp-field label="Workspace handle" description="Lowercase letters, numbers and dashes.">
  <tp-input id="input-controlled" mono value="northwind-studio"></tp-input>
</tp-field>`}
  script={`const input = document.querySelector('#input-controlled');
input.onValueChange = (event) => {
  input.value = event.detail.value.toLowerCase().replace(/[^a-z0-9]+/g, '-');
};`}
/>

Without an assignment the proposal is rejected and the committed text stays. Mode stays fixed for an instance lifetime. A rejected or canceled edit restores committed text and preserves selection within its bounds. Composition keeps the native draft until composition ends.

### Validation

Native constraints such as `required`, `pattern` and `minlength` validate through the owning Field, which shows the error and wires `aria-describedby`. `error` and `invalid` set an explicit error from your own validation.

<Preview
  width="3"
  title="Error"
  align="stretch"
  code={`<tp-field label="Username" error="That username is taken." invalid>
  <tp-input name="username" default-value="ada"></tp-input>
</tp-field>`}
/>

### States

<Preview
  width="3"
  title="Disabled and read-only"
  align="stretch"
  code={`<tp-stack  gap="4">
  <tp-field label="Workspace" disabled>
    <tp-input default-value="tweakpad"></tp-input>
  </tp-field>
  <tp-field label="Project ID">
    <tp-input readonly default-value="prj_8f2c41"></tp-input>
  </tp-field>
</tp-stack>`}
/>

Disabled omits the value from form data. Read-only keeps it, along with selection and focus.

Native form reset restores an uncontrolled default with `form-reset`; controlled reset does not propose or replace owner state. State restoration restores uncontrolled strings. Enter uses the associated form's default submitter; composition does not submit. File input retains its native file list and serializes files without duplicate participants.

### Passwords

`revealable` adds a Toggle at the end of a password Input that shows the value as plain text, so people can check what they typed. The value is hidden again when its form submits or resets. `reveal-label` renames the Toggle for another language.

<Preview
  width="3"
  title="Revealable password"
  align="stretch"
  code={`<tp-field label="Password">
  <tp-input type="password" name="password" autocomplete="current-password" revealable></tp-input>
</tp-field>`}
/>

### Mobile keyboards

`inputmode` picks the on-screen keyboard without changing the type, and `enterkeyhint` labels its Enter key, such as `next` on a field that leads to another and `go` on the last one.

<Preview
  width="3"
  title="Keyboard hints"
  align="stretch"
  code={`<tp-stack gap="4">
  <tp-field label="Email">
    <tp-input type="email" name="email" autocomplete="email" enterkeyhint="next"></tp-input>
  </tp-field>
  <tp-field label="Discount code">
    <tp-input name="code" inputmode="numeric" enterkeyhint="done"></tp-input>
  </tp-field>
</tp-stack>`}
/>

### Anatomy and customization

The native `<input>` is a real element in your tree: it renders into the Input's light DOM (`tp-input > input`), shares the Input's form owner and submits natively, so browser autofill and password managers classify and fill it like any form field. Customize semantic tokens, the presentation dictionary, `partPresentation.input`, or style `tp-input > input` directly; `::part(input)` does not apply because the editor is not in the shadow root. Keep caret, selection, autofill and type-specific affordances visible.

Native form serialization follows the editable input's current representation, including type sanitization, while the controlled owner value remains its supplied value. An empty named file input submits the native empty File; unnamed inputs do not contribute data.

### Inline

<Preview
  width="3"
  title="Inline"
  align="stretch"
  code={`<tp-stack  gap="2">
  <tp-input
    variant="inline"
    label="Display name"
    name="display-name"
    default-value="Rowan"></tp-input>
  <tp-input
    variant="inline"
    label="Time zone offset"
    name="offset"
    type="number"
    default-value="2"></tp-input>
  <tp-select variant="inline" label="Language" name="language" default-value="pt">
    <option value="en">English</option>
    <option value="pt">Português</option>
    <option value="ja">日本語</option>
  </tp-select>
</tp-stack>`}
/>

`variant="inline"` fits the Input into one row the height of a control, with `label` at the start and the value at the end, so it stacks with other inline controls such as an inline Select. A press on the label edits the value. Inside a Field, the Field's label moves into the row.

While the row is hovered or focused, a Copy button beside the label copies the value; `copyable="false"` removes it. Password and file Inputs never show it.

A number value sits between a decrement and an increment arrow in place of the browser's spin buttons. Hold an arrow to keep stepping; the Arrow keys step the focused value too, ten steps at a time with Shift. `step` sets how far each step moves, and `precision` how many decimals the value keeps and shows, which defaults to the decimals of `step`.

<Preview
  width="3"
  title="Number steps"
  align="stretch"
  code={`<tp-stack  gap="2">
  <tp-input
    variant="inline"
    label="Line height"
    name="line-height"
    type="number"
    step="0.1"
    min="1"
    max="3"
    default-value="1.5"></tp-input>
  <tp-input
    variant="inline"
    label="Opacity"
    name="opacity"
    type="number"
    step="0.05"
    precision="2"
    min="0"
    max="1"
    default-value="0.8"></tp-input>
</tp-stack>`}
/>

`unit` shows a unit after the value, such as `px`, `rem` or `deg`; it is not part of the value, and the editor announces it as its description. An Icon in the `icon` slot leads the row, outside its boundary.

    variant="inline"

    type="number"
    unit="em"
    step="0.01"

    variant="inline"

};
for (const icon of document.querySelectorAll('#input-inline-units tp-icon')) icon.icon = icons[icon.dataset.icon];`}
/>
